## EventScrape compatibility

The deployed EventScrape upload action was run against all 14 previously scraped local-test events using the existing application password and local WordPress setting. Result: **14 updated, 0 failed, 0 skipped, 5 with warnings**. Read-back comparisons preserved post IDs, draft status, content, category assignments, featured images and all 18 occurrence date ranges. A separate direct REST test confirmed the five requested images return `local_copy` warnings while keeping their prior images; invalid Basic credentials returned HTTP 401.

The real integration account remains draft-only. Publishing now requires `publish_events`; this is intentional enforcement rather than a reason to silently widen that account's permissions. The local copy's outbound-image protection remains enabled.
